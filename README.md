# Flame in Freefall: Microgravity Combustion Research & STEM Platform

[![NASA Space Apps Challenge](https://img.shields.io/badge/NASA%20Space%20Apps-Sarawak%202026-blue.svg)](https://www.spaceappschallenge.org/)
[![Python Version](https://img.shields.io/badge/python-3.11-brightgreen.svg)](https://www.python.org/)

> **Challenge topic:** *Flame in Freefall: AI-Powered Fire Safety Insights from Microgravity Combustion Data*
> An interactive dashboard that combines verified NASA microgravity combustion records, a separately labelled ground-based
> fire model, and an educational physics sandbox. Every number shown says where it came from and what kind of result it is.

Independent student project; not affiliated with or endorsed by NASA.

---

## What is real, what is modelled

Every output in the dashboard and the API carries one of these labels. Statuses are **computed** by
`src/provenance_audit.py` and `src/run_cv_evaluation.py`, never typed in.

| Label | Meaning | Where it appears |
|---|---|---|
| `VERIFIED_SOURCE` / `REAL_MEASUREMENT` | Byte-identical to an official source file (checksum or rebuild) | Evidence tab, MaCFP preview |
| `UNVERIFIED_SOURCE` | Cannot be traced to an authoritative file | Shown if a source check fails |
| `SYNTHETIC_DEMO` | Generated by a script, not measured | Only via `--include-demo` |
| `MODEL_PREDICTION` | Output of a trained model | Prediction tab, audit plots |
| `SIMULATED_RESULT` | Output of the educational physics formulas | STEM Analysis, 2D Sandbox |
| `NOT_EVALUATED` | No score produced, with the reason | Audit tab |

## Data sources

| Dataset | What it is | Status check |
|---|---|---|
| **NASA BASS-II** (PSI-25, DOI `10.60555/4qc4-de67`) | 129 solid-fuel flame tests on the ISS: materials, flow settings, O₂/CO₂/CO readings. No flame-spread speed column. | SHA-256 + size against NASA metadata (`config/data_sources.json`) |
| **NASA FLEX** (PSI-69, DOI `10.60555/mbq8-0451`) | 274 droplet-combustion tests on the ISS: fuel, pressure, atmosphere, droplet sizes, burning-rate constant (mm²/s), test outcome | Same |
| **MaCFP PMMA cone calorimeter** ([MaCFP/matl-db](https://github.com/MaCFP/matl-db), commit `b72eb23`) | 54 ground-based (1 g) PMMA burns from 10 labs | Rebuilt byte-for-byte from the pinned commit |

Both NASA tables are stored unchanged in `data/raw/nasa_psi/` and list `CC0-1.0` in NASA's PSI metadata.
Column meanings follow NASA/TP-2015-216046 Appendix A.1 / Table IX (FLEX) and the PSI-25 ReadMe (BASS-II).
For example, the FLEX header "Burning rate; mm" is a truncated `mm²/s`, and the "CO" column is CO₂.

> **History:** earlier versions displayed 80 formula-generated rows labelled as NASA data, and scored models on a BASS-II
> target computed from an input. Those files are kept unchanged in `data/legacy/`, `reports/legacy/` and `src/legacy/`
> (with a README each). `reports/data_provenance_audit.json` records the evidence.

## Quick start

```bash
git clone https://github.com/StudyGeng/Nasa-Space-Apps-Sarawak.git
cd Nasa-Space-Apps-Sarawak
python3.11 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install --upgrade pip && pip install -r requirements.txt

streamlit run src/app.py                                # dashboard at http://localhost:8501
python -m uvicorn app.main:app --reload                 # optional API, docs at http://127.0.0.1:8000/docs
pytest -q                                               # tests
```

The dashboard only reads committed files (`data/processed/`, `reports/`, `models/`), so it runs offline and on
Streamlit Community Cloud. Use Python 3.11; TensorFlow 2.16 does not support newer versions.

## Reproducible pipeline

```bash
python -m src.fetch_nasa_psi_tables          # download official PSI tables; refuses files whose size/SHA-256 differ
python -m src.fetch_nasa_psi_tables --verify # offline check of the stored files
python -m src.build_dashboard_data           # raw tables -> data/processed/dashboard_records.csv (values copied unchanged)
python -m src.build_task_datasets            # FLEX modelling table + exclusions with reasons
python -m src.build_measured_cone_dataset    # MaCFP summaries (needs a clone of MaCFP/matl-db in data/raw/macfp-matl-db)
python -m src.provenance_audit               # computes statuses -> reports/data_provenance_audit.json, provenance_mapping.csv
python -m src.run_cv_evaluation              # leakage-audited 5x5 group CV -> reports/cv_*.csv/json, data_audit_report.json
python -m src.train_spacecraft_fire_model    # retrains the deployed MaCFP network (reproduces the saved checkpoint)
python -m src.train_flex_models              # exports the deployed FLEX Ridge + logistic models -> models/flex_*_v1.json
```

Optional local AI pipeline for the SI tab (NVIDIA GPU, e.g. RTX 3060 12 GB; `pip install -r requirement.txt` first):

```bash
python -m scripts.download_model_assets        # base weights once (3.09 GB open weights; offline afterwards)
python -m scripts.build_local_retrieval_index  # FAISS cosine index from data/knowledge/ -> data/vector_index/
python -m scripts.prepare_ai_dataset           # training splits -> data/ai_training/
python -m scripts.train_local_llm              # BF16 LoRA fine-tune -> models/local_research_llm/adapter_v1
python -m scripts.evaluate_local_llm           # base vs LoRA benchmark -> reports/local_ai_comparative_benchmark.*
```

## Prediction tasks and evaluation

`config/target_registry.json` defines each task's target, unit and its evidence, its label mapping, its allowed inputs
(and whether each is known before or after a test), and its independent grouping unit. Physically different quantities
are never merged into one target.

| Task | Data | Target / label | Group unit | Status |
|---|---|---|---|---|
| `macfp_pmma_peak_hrr` | MaCFP (ground) | peak HRR, kW/m² (after-test summary) | laboratory | evaluated |
| `flex_droplet_burning_rate_constant` | FLEX (ISS) | d²-law constant K, mm²/s | test date | evaluated |
| `flex_extinction_outcome` | FLEX (ISS) | Extinction = 1, Completion = 0, Disruption excluded | test date | evaluated |
| `bass_ii_flame_spread_speed` | BASS-II (ISS) | spread speed | — | `NOT_EVALUATED`: not in the table |
| `bass_ii_extinction` | BASS-II (ISS) | extinction | — | `NOT_EVALUATED`: not recorded |

**Protocol** (`src/group_cv.py`, `src/run_cv_evaluation.py`):
- **Splits:** 5 documented seeds × 5 outer folds, built from whole groups. scikit-learn 1.5's `GroupKFold` cannot shuffle, so a tested seeded group splitter is used instead.
- **Model selection:** each outer-training partition is split into inner-train and inner-validation groups, and tuning grids are chosen on inner validation only.
- **Scoring:** the selected setting is refit on the outer-training partition and scored on the outer test fold exactly once.
- **Preprocessing:** imputation and scaling live inside each model pipeline, fitted on training rows only.
- **Threshold:** the classification threshold is fixed in the registry and never tuned.
- **Leakage audit:** every split is audited programmatically (no shared groups between any two partitions, no record in two partitions, each group tested once per repeat), and the dashboard re-checks the saved manifest independently.
- **Dependence:** the 25 folds are correlated re-splits, not independent experiments.

**Results at the time of writing (2026-10-24; the dashboard always reads the current `reports/`):**
- **MaCFP peak HRR:** Ridge has the lowest error. The deployed network's configuration scores lower under this protocol than the single 5-fold run stored in its metadata.
- **FLEX burning-rate constant:** Ridge explains about 70% of the variance on unseen test days.
- **FLEX extinction:** logistic regression reaches balanced accuracy of about 0.68 (ROC-AUC about 0.79) against 0.5 for the baseline.

Exact means, spreads and every fold are in `reports/cv_summary.json` and `reports/cv_fold_metrics.csv`.

## Dashboard tabs

**Above the tabs: What this means for crew fire safety.** Six takeaways for astronauts, each with its number computed live (`app/services/insights.py`): airflow keeps a fire alive in orbit, more oxygen burns faster, CO₂ slows the flame, flames do not reliably go out on their own, the amount of material drives toxic CO, and heat and smoke do not rise without gravity. Each card is badged `REAL_MEASUREMENT` (NASA FLEX or BASS-II data) or `SIMULATED_RESULT` (sweep or 2D model) and names the tab that holds the evidence.

1. **Evidence Explorer.** Per-material (BASS-II) and per-fuel (FLEX) aggregates computed live from the verified tables:
   - **Animated cards:** illustrations modelled on NASA ISS photos, not footage.
   - **Data provenance panel:** evidence for each dataset's status.
   - **Record inspector:** traces any row to its file, row number, original column and unit.
   - **What the ranking means:** plain-language findings and a crew-safety takeaway, every number computed from the ranking (`ranking_insights` in `app/services/research_engine.py`), with groups under 5 tests flagged as too small to rank.
2. **STEM Analysis** (`SIMULATED_RESULT`). Parameter sweeps of gravity, airflow and oxygen using scaling formulas (Richardson number, buoyancy velocity). The flame-spread index is a relative proxy with no physical units. The explanation under the charts is written from each sweep's own numbers (smothering threshold, growth, the airflow or gravity where Ri = 1) plus a crew-safety takeaway.
3. **2D Physics Sandbox** (`SIMULATED_RESULT`). An educational reduced-order model that computes:
   - densities;
   - buoyancy force;
   - reduced gravity g′;
   - buoyancy velocity u_b;
   - diffusion width;
   - the hot-gas centroid path.

   The temperature map is an illustrative Gaussian, not a CFD solution. The tab lists every equation, assumption and limitation (`config/simulation_model.json`).
4. **Scientific Audit.** Every task's status, the leakage re-check, model diagrams and scores, fold-by-fold results, measured-vs-predicted plots, and download links for all reports.
5. **AI Predictions & Research**, three sub-tabs: two trained models (`MODEL_PREDICTION`) and the local research AI.
   **Microgravity droplet flame (FLEX · ISS):** pick a fuel (n-heptane or methanol), pressure, O₂/CO₂/He mix and droplet size,
   or load one of six atmospheres NASA actually tested.
   - **Predictions:** burning-rate constant K (Ridge) and whether the flame goes out before the fuel is used up (logistic
     regression), plus the d²-law burn-out time d₀²/K.
   - **Why:** both models are linear, so each prediction is split exactly into one push per input, measured from the average
     NASA test.
   - **Pictures, not just numbers:** the same droplet burning on Earth (a tall, flickering flame) next to the ISS run
     (a free-floating droplet in a steady ball of flame), drawn to scale with NASA FLEX colours. The droplet shrinks
     at the predicted rate (d²-law) and the run ends the way the flame-out model says. Three meters place the burning
     rate on NASA's measured range, the flame-out score on its 0–1 scale, and show what happened in the closest real
     tests. Two step charts build each answer from an average NASA test, one push per input. A card per input says in
     plain words what it does, gives the AI's answer with only that input changed, and the physics behind it (a test
     checks each card's stated direction against the fitted weights). Longer notes sit in folded boxes.
   - **Real NASA tests close to this:** same fuel, pressure within 10 %, each gas within 2–5 points; if there are none, the
     tab says the model is combining other conditions.
   - **Accuracy and limits:** the nested-CV scores are shown next to the prediction. Inputs outside the tested ranges are
     refused. The flame-out score comes from a class-balanced model, so it ranks risk but is not a probability.
   **Ground PMMA burn (CSV upload):** the MaCFP network estimates peak HRR from an after-test burn summary.
   - **Preview:** two real burns, measured vs out-of-fold prediction.
   - **Inputs:** two of the inputs come from the same HRR curve, so this is an after-test estimate, not a forecast.
   - **Scope:** ground-based PMMA only. It is not validated for microgravity, spacecraft or fire-safety decisions.
   - **Hazard flag:** the 350 kW/m² rule cannot be validated, because every measured peak is above it.
   **🧠 Ask the research AI (SI Research Intelligence, local GPU only):** ask a space-fire question in English: a local
   FAISS index retrieves passages from `data/knowledge/nasa_combustion_corpus.json` and a locally fine-tuned
   `Qwen2.5-1.5B-Instruct` (LoRA) answers with their citations, with no remote API (`app/services/local_llm_service.py`).
   - **Where it runs:** it needs an NVIDIA GPU and the packages in `requirement.txt`. On Streamlit Cloud the sub-tab says
     the engine is not installed and shows the last local benchmark instead.
   - **Results so far:** fine-tuned on 12 examples (6.8 s on an RTX 3060), it scored the same as the base model on 4 test
     questions (`reports/local_ai_comparative_benchmark.json`).
   - **Knowledge passages:** team-written summaries, not verbatim NASA text; their report numbers are still being checked
     (`docs/SCIENTIFIC_AUDIT.md`, section 12), so the sub-tab marks them `UNVERIFIED_SOURCE`.

## Tests

`pytest -q` covers:
- **Physics:** the sandbox's physics limits.
- **Splitting:** group-disjoint, reproducible splits, plus an audit that catches injected leakage.
- **Data rules:** cell parsing, material classes, duplicate and invalid-entry exclusions, and label mapping.
- **Provenance:** official checksums, generator output classified as synthetic, unregistered data classified as unverified.
- **Registry:** units and targets declared per task.
- **Pipeline:** preprocessing fitted on training rows only, refusal to score unverified data, units or labels, and handling of single-class folds.
- **Reports and checkpoint:** consistency of the generated reports, and the saved checkpoint matching its training file.
- **API:** status fields in API responses.
- **Deployed FLEX models:** the JSON export reproduces the scikit-learn pipeline exactly, retraining gives the committed
  file, the file matches its data hash and the CV report, contributions add up, and out-of-range inputs are refused.
- **Interpretation texts:** every number in the STEM and ranking explanations matches the computed values.
- **Crew takeaways:** each front-page number is recomputed from the data or models and checked against the text.
- **Local AI (SI tab):** `tests/test_local_ai_pipeline.py`, skipped unless torch and the local model weights are installed.
- **Dashboard:** an explicit error when the provenance report is missing.
